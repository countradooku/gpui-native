# GPUI Native contributor guide

## Architecture

- Keep framework adapters thin. Each framework owns component state and
  reconciliation; GPUI owns layout, input, text shaping, painting, focus,
  scrolling, and windows. `crates/gpui-core` and `packages/core` must not
  depend on Vue, React, Svelte, or another framework adapter.
- Keep Vue-specific components, composables, refs, and reconciliation in
  `packages/vue`. Future adapters belong in their own `packages/<framework>`
  directory and use the same native mutation and event protocol.
- Search the pinned Zed/GPUI revision before adding a platform workaround.
  Prefer an existing GPUI API or a small upstreamable GPUI change over a
  second renderer-specific implementation.
- Preserve parity with the sibling `gpuix` native engine unless Vue's runtime
  requires a different adapter. Translate public React hooks and props into
  Vue composables and typed host props; do not copy React state machinery.
- All framework mutation waves go through `applyBatch`. Decode and validate a batch
  before mutating the retained tree, and keep style/custom-prop values raw
  until the one outer JSON serialization.

## Native text and components

- Route selectable and searchable text through the shared text run, selection,
  and highlight pipeline. A native component must not invent a separate text
  painter or matcher.
- Layout-affecting code/diff/markdown numbers belong in theme metrics, not Rust
  constants. A theme prop change must be enough to tune them.
- `<code>` is a bare primitive. The app owns its fill, border, radius, padding,
  and any language header.
- Custom-element adapters own their retained state and must reset removed props,
  release state when an id changes type, and report supported props/events.

## Browser and platform work

- The browser build uses `gpui_platform::single_threaded_web()`. Keep it free
  of shared-memory requirements so static GitHub Pages hosting continues to
  work without COOP/COEP headers.
- Keep native-only N-API code and Wasm bindings behind explicit target cfgs.
  Public capabilities should have matching `WebGpuiRenderer` and TypeScript
  methods when GPUI Web supports them.
- The GPU-backed test renderer is supported on macOS and Windows. Linux uses
  the production wgpu renderer but does not expose screenshot test support.

## Verification

Run the checks relevant to a change, and run the full set before handoff:

```bash
bun run check
bun test
cargo test --workspace --all-features
bun run build:native
bun run test:native
bun run build:pages
```

`packages/core/index.d.ts` is generated by the N-API build. Do not
hand-edit it. `web/pkg`, `dist-pages`, package `dist` folders, and native
binaries are generated and ignored.
